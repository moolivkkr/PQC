## 1. H1 and lead paragraphs
H1: Java runbook

The JSSE provider inside the JVM decides, not the OS OpenSSL or the base image. JDK 25.0.5 and later (released 2026-10-20) offer and prefer X25519MLKEM768 by default, as client and as server (Oracle 25.0.5 release note, JDK-8314323). JDK 8 to 21 have no ML-KEM TLS group: put Bouncy Castle's JSSE provider (BCJSSE) first with the pq-tls agent or a java.security override, or upgrade.

H3: java.security override (static registration: containers and EC2, not Lambda)
pq-tls/bc-static.security (JDK 11, 17, 21; load with -Djava.security.properties=<path>)
```properties
# Appended to $JAVA_HOME/conf/security/java.security. Bouncy Castle JSSE goes before SunJSSE;
# the BC JCA provider goes last so other crypto keeps resolving to the JDK providers.
```
Compare the list with $JAVA_HOME/conf/security/java.security in your exact image first: a vendor that adds or reorders providers needs the same change here. Pair it with -Djdk.tls.namedGroups=X25519MLKEM768,x25519,secp256r1,secp384r1. JDK 8 uses class names (sun.security.provider.Sun, ..., com.sun.net.ssl.internal.ssl.Provider) in $JAVA_HOME/jre/lib/security/java.security; a JDK 8 variant was not tested.
