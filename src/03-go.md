# Go

## Problem statement

Go's own `crypto/tls`, compiled into the binary, controls every handshake. OpenSSL, the OS crypto policy, the base image and the Lambda runtime play no part (Tested: an AL2023 host or image with `update-crypto-policies --set DEFAULT:PQ`, and Amazon Linux 2 with OpenSSL 1.0.2, gave the same results as `scratch`). Five inputs decide the result:

| Input | Classical when | Evidence |
| --- | --- | --- |
| Toolchain | Go 1.23 or older (no ML-KEM; 1.23 offers only the Kyber draft) | Tested |
| `go` line in the main module's `go.mod` (sets `DefaultGODEBUG`) | Below 1.24 (`tlsmlkem=0`), whatever the toolchain | Tested |
| `GODEBUG` at run time | `tlsmlkem=0` | Tested |
| `tls.Config` in your code or a library | `CurvePreferences` without a hybrid, or `MaxVersion: tls.VersionTLS12` | Tested |
| FIPS 140-3 mode | Go 1.24 FIPS, or boringcrypto with `crypto/tls/fipsonly`; Go 1.25 `fips140=only` fails every handshake | Tested |

The handshake still succeeds over X25519, so nothing breaks and nothing is logged: the gap is silent (Tested). The risk is harvest-now-decrypt-later; hybrid X25519MLKEM768 removes it for new sessions. Certificates are a separate track (see Certificates (ML-DSA)). Not tested: the Microsoft build of Go and Red Hat's Go toolset, which can route crypto to OpenSSL in FIPS mode.

## Quick start by compute type

The fix is the same everywhere: build with Go 1.26+ and `go 1.26` in `go.mod`. Where the `go` line can't move yet, set `GODEBUG=tlsmlkem=1,tlssecpmlkem=1` in the deployment (needs a Go 1.24+ binary; Go ignores unknown `GODEBUG` names at run time, [Documented](https://go.dev/doc/godebug)). The compute type only changes where you check, where the variable goes and how you roll back.

**What to check (every compute type):** `go version -m <binary>` shows `go1.24` or later and no `tlsmlkem=0`; the deployment sets no `GODEBUG=tlsmlkem=0`; `go-pq-lint.sh` finds no blocking `tls.Config` ([configs/go/go-pq-posture.sh](REPO/configs/go/go-pq-posture.sh), [configs/go/go-pq-lint.sh](REPO/configs/go/go-pq-lint.sh)).

| Compute | Where to check | The one change | How to verify | How to roll back | Evidence |
| --- | --- | --- | --- | --- | --- |
| Lambda zip (`provided.al2023`, `provided.al2`) | `bootstrap` from the deployed zip (`aws lambda get-function` gives the code URL); function `Environment` | Rebuild `bootstrap` with Go 1.26+ and `go 1.26`. Interim: `GODEBUG` in `Environment.Variables` | CloudTrail `tlsDetails.keyExchange` for the function role's KMS, STS, IAM, Secrets Manager and ACM calls; the function's own `CurveID` log | `GODEBUG=tlsmlkem=0,tlssecpmlkem=0` in the function environment, or shift the alias back to the previous version | Tested (e2e, 75 zip cases) |
| Lambda container image | Builder stage `golang:` tag; binary copied out of the image | Builder `golang:1.26`, `go 1.26`; final stage `public.ecr.aws/lambda/provided:al2023` | As for zip | Function environment overrides image `ENV`; or the previous image digest | Tested (e2e, 2 image cases) |

Interim: `GODEBUG` in the task definition | CloudTrail; application `CurveID` log; for a load balancer target, the ALB/NLB target leg | New task definition revision with `GODEBUG=tlsmlkem=0,tlssecpmlkem=0`, or the previous image tag | Tested (e2e, 22 client + 4 target cases) |
| ECS on EC2, EKS | As for Fargate; pod `env` on EKS | As for Fargate; the node OS doesn't matter | As for Fargate, plus Zeek `ssl.log` on mirrored node ENIs | As for Fargate; on EKS a pod `env` change rolls the Deployment | Tested on ECS EC2 (5 client + 1 target cases); EKS not run (Unverified, same image) |

**Lambda: shared kit pieces.** The `pq-tls` layer (`AWS_LAMBDA_EXEC_WRAPPER`) does nothing for Go: it has no `provided.*` branch and Go ignores `OPENSSL_CONF` (Tested: Go 1.23 stayed classical, Go 1.27 stayed PQ, 4 cases). A Go 1.23 function that can't be rebuilt soon can send its calls through the `pq-egress` extension, which makes the TLS connection with X25519MLKEM768 (Tested, 3 cases; not tested for AWS SDK calls; see Solutions by compute type). The `go1.x` managed runtime is retired; use `provided.al2023` ([AWS](https://docs.aws.amazon.com/lambda/latest/dg/golang-package.html)). `provided.al2` works, but AWS blocks updates to it from 2027-08-31.

| --- | --- | --- | --- | --- | --- |

| 1.26.x (supported; 1.26.11 tested) | Same rule as 1.27 | `CurvePreferences`; `GODEBUG` (`tlsmlkem=0` beats an explicit list) | Same as 1.27 | **Target.** Build with 1.26+, `go 1.26` | Tested |
| 1.25.x (no security fixes since 1.27.0, 2026-08-19) | Yes if `go` ≥ 1.24, X25519MLKEM768 only | Same as 1.26 | `on`: X25519MLKEM768 + P-256, P-384, P-521; `only`: **every handshake fails** | Upgrade to 1.26 | Tested |
| 1.24.x (unsupported) | Yes if `go` ≥ 1.24; **no** with `go 1.23` or lower (`tlsmlkem=0`), as client and as server | Same | `on` or `only`: P-256, P-384, P-521, **no PQ** | Upgrade; interim `GODEBUG=tlsmlkem=1` | Tested |

Support: "each major Go release is supported until there are two newer major releases", so 1.27 and 1.26 today ([release history](https://go.dev/doc/devel/release); Documented).

**Decision guide**

| `go version -m` or the code shows | Do this |
| --- | --- |
| `go1.23` or older | Rebuild with Go 1.26. Nothing else helps (or `pq-egress` on Lambda, interim) |
| `tlsmlkem=0` in `DefaultGODEBUG` | Raise the `go` line to 1.26; interim `godebug tlsmlkem=1` in `go.mod` or `GODEBUG=tlsmlkem=1` |
| `CurvePreferences` without a hybrid, or `MaxVersion: tls.VersionTLS12` | Fix the setting (case F) |
| `GOFIPS140=`, `fips140=on` or `GOEXPERIMENT=boringcrypto` | Go 1.26+ native FIPS, not boringcrypto; AWS SDK fix (cases G, H) |
| None of these | Already PQ. Verify (How to test) and move on |

### Detail: toolchain and go line

Client with default `tls.Config` against one server per group (Tested: e2e on Lambda, ECS and EC2, and `golang` images pinned by digest, linux/arm64).

| Toolchain | `go` line | X25519MLKEM768 | SecP256r1MLKEM768, SecP384r1MLKEM1024 | Classical server still works |
|----|----|----|----|----|
| 1.27.4 | 1.27 | Yes | Yes | Yes |
| 1.27.4 | 1.23 | No (`tlsmlkem=0`) | No | Yes |
| 1.26.11 | 1.26 | Yes | Yes | Yes |
| 1.26.11 | 1.25 | Yes | No (`tlssecpmlkem=0`) | Yes |
| 1.26.11 | 1.23 | No | No | Yes |
| 1.25.14 | 1.25 | Yes | No (added in 1.26) | Yes |
| 1.25.14 | 1.23 | No | No | Yes |
| 1.24.13 | 1.24 | Yes | No | Yes |
| 1.24.13 | 1.23 | No | No | Yes |
| 1.23.12 | any | No (no ML-KEM in 1.23) | No | Yes |

All rows Tested. The rules behind the table:

1. **Toolchain** sets what exists: 1.24 added X25519MLKEM768, 1.26 added the two SecP hybrids to the defaults, 1.27 added opt-in pure `MLKEM1024`, offered only when listed in `CurvePreferences` ([Go 1.26](https://go.dev/doc/go1.26), [Go 1.27](https://go.dev/doc/go1.27); Tested).
2. **The `go` line** of the main module (or `go.work`) sets the defaults: below 1.24 gives `tlsmlkem=0`, below 1.26 gives `tlssecpmlkem=0`. A dependency's `go.mod` doesn't count ([Documented](https://go.dev/doc/godebug); Tested).
3. **Override at build time** without raising the `go` line: `godebug tlsmlkem=1` in `go.mod` (Go 1.23+ toolchains) or `//go:debug tlsmlkem=1` above `package main`. Both put `tlsmlkem=1` into `DefaultGODEBUG` (Tested 1.24 to 1.27). Add `tlssecpmlkem=1` on 1.26+ only: a 1.24 or 1.25 build fails with `unknown godebug "tlssecpmlkem"` (Tested, e2e build log; [Documented](https://go.dev/doc/godebug)).
4. **Run-time `GODEBUG`** beats both: `tlsmlkem=1` turns PQ on with no rebuild, `tlsmlkem=0` turns it off (Tested). Unknown names are ignored at run time, so one value `tlsmlkem=1,tlssecpmlkem=1` is safe on 1.24+ ([Documented](https://go.dev/doc/godebug); tested on 1.26 only).
5. **Explicit `CurvePreferences` vs `tlsmlkem=0`.** On 1.24 to 1.26, `tlsmlkem=0` drops X25519MLKEM768 even from an explicit list. From 1.27 an explicit list wins ([Documented](https://go.dev/doc/go1.27); Tested both).

Raising the `go` line changes other defaults too. Going to 1.27 removes the `tls10server`, `tlsrsakex`, `tls3des`, `tlsunsafeekm`, `x509keypairleaf` and `asynctimerchan` settings ([Go 1.27](https://go.dev/doc/go1.27); Documented), so run the service tests. The `GODEBUG` route changes only the TLS groups.

## Cases: what to change

Every case below was tested with Go 1.24.13 (`go 1.24`), 1.25.14 and 1.26.11 against OpenSSL 3.5.7 and Go test servers, unless a row says otherwise; Go 1.23.12 and `go 1.22`/`1.23` builds were classical in every row, so the case was never the cause. Programs: [tests/deep/go/v2/cases/main.go](REPO/tests/deep/go/v2/cases/main.go), [tests/deep/go/v2/deps/main.go](REPO/tests/deep/go/v2/deps/main.go); outputs: [tests/deep/go/v2/run-v2.out](REPO/tests/deep/go/v2/run-v2.out), [run-v2b.out](REPO/tests/deep/go/v2/run-v2b.out), [run-v2c.out](REPO/tests/deep/go/v2/run-v2c.out).

### A. Simple client

**Who this is.** No TLS settings in code: `grep -rnE --include='*.go' 'tls\.Config|TLSClientConfig|CurvePreferences|MaxVersion' .` finds nothing. You use `http.Get`, the AWS SDK default client, or a driver with a DSN.

**What happens today.** PQ when the toolchain and the `go` line are both 1.24+; classical otherwise (Tested). **What to change.** Nothing in code: raise the `go` line and rebuild. **Side effects.** The ClientHello grows by about 1.2 KB (Pitfalls).

Rule for every library: pass a `tls.Config` without `CurvePreferences`, or none. Tested with Go 1.26.11 (`go 1.26`) against a Go server that accepts only X25519MLKEM768:

| Client | Version tested | Where TLS is set | PQ by default | Evidence |
|----|----|----|----|----|
| `crypto/tls` `Dialer`, `tls.Dial` | stdlib | `tls.Config` | Yes | Tested |
| `net/http` default client, `DefaultTransport.Clone()` | stdlib | `Transport.TLSClientConfig` | Yes | Tested (also e2e) |
| gRPC-go | v1.85.0 | `credentials.NewTLS(cfg)` | Yes; it doesn't set `CurvePreferences` | Tested |
| AWS SDK for Go v2 | v1.48.0 | `awshttp.NewBuildableClient()` | Yes, outside FIPS mode | Tested (also e2e) |
| AWS SDK for Go v2, FIPS mode | v1.48.0 | same | **No**: the SDK forces P-256/P-384/P-521 | Tested (also e2e); fix in case H |
| pgx (and `database/sql` via `pgx/v5/stdlib`) | v5.13.0 | `sslmode=require/verify-full`, `ConnConfig.TLSConfig` | Yes | Tested with `sslnegotiation=direct` |
| go-redis | v9.23.0 | `Options.TLSConfig` | Yes | Tested |
| segmentio/kafka-go | v0.4.51 | `Dialer.TLS`, `Transport.TLS` | Yes | Tested |
| IBM/sarama | v1.61.1 | `Config.Net.TLS.Config` | Yes | Tested |
| lib/pq, mongo-go-driver, others | — | their `tls.Config` | Probably, if they don't set `CurvePreferences` | Unverified: grep them (case F) |

Whether the far end accepts ML-KEM is a server question: see AWS service endpoints and Databases and data services. If a team insists on an explicit list, keep the hybrids in it; since Go 1.24 the order of `CurvePreferences` is ignored ([Documented](https://pkg.go.dev/crypto/tls#Config)).

``` go
tr := http.DefaultTransport.(*http.Transport).Clone()
tr.TLSClientConfig = &tls.Config{MinVersion: tls.VersionTLS12} // no CurvePreferences
client := &http.Client{Transport: tr}

// Only if a list is mandatory (Go 1.26+ constants):
cfg := &tls.Config{CurvePreferences: []tls.CurveID{
    tls.X25519MLKEM768, tls.SecP256r1MLKEM768, tls.X25519, tls.CurveP256}}
```

### B. Simple server

**Who this is.** `http.ListenAndServeTLS`, frameworks on `net/http` (chi, gin, echo), or a gRPC server with `credentials.NewTLS`, with no `CurvePreferences`.

**What happens today.** With 1.24+ and `go` ≥ 1.24, RSA and EC servers negotiate X25519MLKEM768 with a PQ client and X25519 with a classical one. The `go` line governs servers too: a 1.24 build with `go 1.22` refused a PQ-only client until `GODEBUG=tlsmlkem=1` was set, with no rebuild (Tested). **What to change.** Nothing beyond the build. **Side effects.** None seen.

| Server setup | PQ client | Classical client | Evidence |
|----|----|----|----|
| `net/http` `ListenAndServeTLS`, default `tls.Config` | X25519MLKEM768 and SecP256r1MLKEM768 negotiated | Works (X25519, or P-256 on TLS 1.2) | Tested, Go 1.26.11 |
| `CurvePreferences: {X25519, P256}` (the pitfall) | PQ-only client **fails**; hybrid-capable client silently gets X25519 | Works | Tested |
| PQ-only: `MinVersion: TLS13`, `CurvePreferences: {X25519MLKEM768}` | Works | Rejected; TLS 1.2 rejected | Tested |
| gRPC server, `credentials.NewTLS(default)` | X25519MLKEM768 with ALPN h2 | Works | Tested |

``` go
srv := &http.Server{Addr: ":8443", Handler: mux,
    TLSConfig: &tls.Config{MinVersion: tls.VersionTLS12}} // no CurvePreferences
log.Fatal(srv.ListenAndServeTLS("/etc/tls/tls.crt", "/etc/tls/tls.key"))
```

**Behind an ALB or NLB TLS listener** (e2e run r1117041043, the load balancer modelled as the client on the target leg): a `net/http` target built with Go 1.26 and `go 1.26` negotiated X25519MLKEM768 under the PQ backend policy, on Fargate and ECS on EC2. Go 1.26 with `go 1.23` stayed classical until `GODEBUG=tlsmlkem=1,tlssecpmlkem=1` was set in the task definition; Go 1.23 stayed classical (rebuild is the only fix). Under the classic backend policy every target negotiated classical TLS 1.2 (Tested, cases `srv-go-*`; see Load balancers).

### C. Existing server certificates in your own files or keystore

**Who this is.** `grep -rnE --include='*.go' 'LoadX509KeyPair|X509KeyPair|GetCertificate|pkcs12\.|DecryptPEMBlock|pkcs8\.' .`

**What happens today.** The certificate store has no effect on key exchange. Every setup below negotiated X25519MLKEM768 with an OpenSSL PQ-only client and X25519 with a classical client (Tested).

| Setup | Code | Which certificate is served | Store change |
| --- | --- | --- | --- |
| RSA 2048 or EC P-256 PEM pair | `tls.LoadX509KeyPair(crt, key)` | RSA or EC | None |
| RSA and EC together | `Certificates: {rsa, ec}` | The **first** the client supports: RSA to a default client, EC to an ECDSA-only client | None; order picks the cert, not the group |
| EC and RSA together | `Certificates: {ec, rsa}` | EC to a default client, RSA to an RSA-only client | None |
| Two hostnames | `Certificates: {a.test, b.test}` | Matched by SNI; unknown SNI gets the first | None |
| Callback | `GetCertificate` by `ClientHelloInfo.ServerName` | Per SNI, with your fallback | None |
| Legacy encrypted PEM (`Proc-Type: 4,ENCRYPTED`) | `x509.DecryptPEMBlock` then `tls.X509KeyPair` | RSA | None |
| Encrypted PKCS#8 (`BEGIN ENCRYPTED PRIVATE KEY`) | `github.com/youmark/pkcs8` `ParsePKCS8PrivateKey` | EC | None |
| PKCS#12, OpenSSL 3 default (AES-256-CBC, PBKDF2, SHA-256 MAC) | `software.sslmate.com/src/go-pkcs12` v0.7.4 `DecodeChain` | EC | None |
| PKCS#12, legacy 3DES/SHA-1 | `golang.org/x/crypto/pkcs12` v0.59.0 `Decode` | RSA | None |
| Same x/crypto package on the OpenSSL 3 default file | `Decode` | Fails at load: `pkcs12: unknown digest algorithm: 2.16.840.1.101.3.4.2.1` | Switch to go-pkcs12 (also e2e) |
| Cert and key PEM in env vars (ECS `secrets`, Lambda env) | `tls.X509KeyPair([]byte(os.Getenv(...)))` | RSA | None (also e2e, client side) |

**What to change.** Nothing in the store: same files, formats, passwords, key types and chains. The `tls.Config` your loader fills must not set `CurvePreferences` without a hybrid, nor `MaxVersion: tls.VersionTLS12`. The one code change any team may need is the PKCS#12 import:

```go
// Was golang.org/x/crypto/pkcs12 (frozen; can't read OpenSSL 3 default files)
import pkcs12 "software.sslmate.com/src/go-pkcs12"

key, leaf, chain, err := pkcs12.DecodeChain(p12Bytes, os.Getenv("TLS_KEY_PASS"))
c := tls.Certificate{PrivateKey: key, Leaf: leaf, Certificate: [][]byte{leaf.Raw}}
for _, ca := range chain { c.Certificate = append(c.Certificate, ca.Raw) }
cfg := &tls.Config{Certificates: []tls.Certificate{c}} // no CurvePreferences
```

The alternative, re-exporting with `openssl pkcs12 -export -keypbe PBE-SHA1-3DES -certpbe PBE-SHA1-3DES -macalg sha1`, keeps 3DES and SHA-1, so prefer the import change. `x/crypto/pkcs12` is frozen and its docs point to go-pkcs12 ([Documented](https://pkg.go.dev/golang.org/x/crypto/pkcs12)).

**Encrypted keys.** The standard library can't read encrypted PKCS#8, and `x509.DecryptPEMBlock` is deprecated as insecure by design ([Documented](https://pkg.go.dev/crypto/x509#DecryptPEMBlock)). In order of preference: keep the key unencrypted inside a secret store (Secrets Manager, Kubernetes Secret, ECS `secrets`) and load it with `tls.X509KeyPair`; decrypt at start-up with `youmark/pkcs8`, the passphrase from Secrets Manager; or move the key to KMS or an HSM (case I). All three loaders were tested above.

**Side effects.** None for PQ. If RSA is listed before EC, default clients get RSA; that was already true.

### D. Custom CA trust

**Who this is.** `grep -rnE 'SystemCertPool|AppendCertsFromPEM|RootCAs|SSL_CERT_FILE|SSL_CERT_DIR|AWS_CA_BUNDLE|WithCustomCABundle|sslrootcert'` in code and deployment files.

**What happens today.** Trust and key exchange are independent (Tested; the first six rows also in e2e on Lambda and Fargate `scratch`):

| Trust setup | Result |
| --- | --- |
| `SSL_CERT_FILE=<bundle>` or `SSL_CERT_DIR=<dir>`, `RootCAs` nil | PQ and fallback OK |
| Neither set, private CA not in the system store (or `scratch` with no bundle) | `x509: certificate signed by unknown authority` (expected) |
| `x509.SystemCertPool()` + `AppendCertsFromPEM` | PQ and fallback OK |
| `RootCAs` = new pool with only the private CA | PQ and fallback OK |
| `RootCAs` = empty pool | Unknown authority (expected) |
| AWS SDK `AWS_CA_BUNDLE` or `config.WithCustomCABundle`, default HTTP client | PQ OK |
| AWS SDK CA bundle + a plain `*http.Client` | **Config error**: `unable to add custom RootCAs HTTPClient, has no WithTransportOptions, *http.Client` |
| gRPC `credentials.NewClientTLSFromFile(ca.pem, ...)` | PQ OK |
| pgx DSN `sslrootcert=` | PQ OK |

**What to change.** Nothing in the truststore. Two traps: `SSL_CERT_FILE` and `SSL_CERT_DIR` replace the default locations rather than adding to them, so the bundle must hold public roots too if the service calls public endpoints ([Documented](https://pkg.go.dev/crypto/x509#SystemCertPool)); and `scratch` or distroless static images have no bundle, so copy one in (`COPY --from=build /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/`). The one code change is for the AWS SDK with your own client:

```go
// Not: a plain *http.Client together with AWS_CA_BUNDLE / WithCustomCABundle (config error)
hc := awshttp.NewBuildableClient().WithTransportOptions(func(t *http.Transport) {
    t.TLSClientConfig = &tls.Config{RootCAs: pool} // no CurvePreferences
})
cfg, err := config.LoadDefaultConfig(ctx, config.WithHTTPClient(hc))
```

**Side effects.** None.

### E. Mutual TLS (client certificates)

**Who this is.** `grep -rnE --include='*.go' 'ClientAuth|ClientCAs|GetClientCertificate|Certificates:' .`

**What happens today.** Client certificates don't change the group (Tested; client side also in e2e: `GetClientCertificate`, PEM from env vars, PKCS#12):

- Go client with an RSA cert in `Certificates` or an EC cert from `GetClientCertificate`: X25519MLKEM768 to a PQ-only mTLS server, X25519 to a classical one.
- Go server with `ClientAuth: tls.RequireAndVerifyClientCert`: RSA and EC clients over X25519MLKEM768, `client_cn` logged; classical clients over X25519.
- No client cert: refused. In TLS 1.3 the client sees `remote error: tls: certificate required` on its first read; the server logs `tls: client didn't provide a certificate`.

**What to change.** Nothing. **Side effects.** None.

### F. Explicit TLS settings that block PQ

**Who this is.** Run [go-pq-lint.sh](REPO/configs/go/go-pq-lint.sh), or:

```sh
grep -rnE --include='*.go' 'CurvePreferences|MaxVersion|CipherSuites|tlsmlkem|tlskyber|fipsonly' . $(go env GOMODCACHE) | grep -v _test.go
grep -rnE 'GODEBUG|godebug' go.mod go.work Dockerfile* *.yaml *.json *.tf 2>/dev/null
```

In the tested dependency versions only the AWS SDK hit (its FIPS list, case H).

| Setting | Client to PQ-only server | Client to classical | As a server | Change to | Evidence |
| --- | --- | --- | --- | --- | --- |
| `CurvePreferences: {X25519, P256}` | Fails: `handshake failure` | X25519 | PQ-only client fails; hybrid client silently gets X25519 | Remove it, or add `tls.X25519MLKEM768` (and `tls.SecP256r1MLKEM768` on 1.26+) | Tested (also e2e) |
| `CurvePreferences: {X25519MLKEM768, X25519, P256}` | X25519MLKEM768 | X25519 | — | Fine; but `tlsmlkem=0` drops the hybrid from it on 1.24 to 1.26 | Tested (also e2e) |
| `MaxVersion: tls.VersionTLS12` | Fails: `protocol version not supported` | TLS 1.2, X25519 | TLS 1.2 only, never PQ | Remove it: the hybrids exist only in TLS 1.3 | Tested (also e2e) |
| `MinVersion: tls.VersionTLS13` | X25519MLKEM768 | X25519 (TLS 1.2-only servers refused) | — | Fine | Tested (also e2e) |
| `CipherSuites` (a TLS 1.2 list) | X25519MLKEM768 | X25519 | PQ on TLS 1.3 | Keep: it doesn't touch TLS 1.3 | Tested (also e2e) |
| `GODEBUG=tlsmlkem=0` at run time | Fails | X25519 | — | Remove it | Tested (also e2e) |
| Go 1.23 with curve 4588 listed by number | Fails even to classical: `tls: CurvePreferences includes unsupported curve` | Fails | — | Upgrade the toolchain | Tested (also e2e) |

**PQ-only enforcement** (internal endpoints, last, after logs show no classical clients):

``` go
cfg := &tls.Config{MinVersion: tls.VersionTLS13,
    CurvePreferences: []tls.CurveID{tls.X25519MLKEM768, tls.SecP256r1MLKEM768}}
```

**Side effects.** Removing `MaxVersion` lets TLS 1.3 through; check peers that pin TLS 1.2 behaviour, such as inspection proxies.

### G. FIPS mode

**Who this is.** `go version -m` shows `GOFIPS140=`, `DefaultGODEBUG=fips140=on` or `GOEXPERIMENT=boringcrypto`, or the environment sets `GODEBUG=fips140=on|only`.

**What to change.** Build with Go 1.26+ and `GOFIPS140=v1.26.0` (or `latest`), not boringcrypto, and add the AWS SDK fix (case H). In FIPS mode `crypto/tls` silently drops non-approved groups ([Documented](https://go.dev/doc/security/fips140)). Groups the client offers (a server that prefers P-256 negotiates P-256):

| Mode | 1.24.13 | 1.25.14 | 1.26.11 | 1.27.4 |
|----|----|----|----|----|
| `fips140=on` | P-256, P-384, P-521: **no PQ**, no X25519 | X25519MLKEM768, P-256, P-384, P-521 | The three hybrids, P-256, P-384, P-521 | Same as 1.26 |
| `fips140=only` | P-256, P-384, P-521 | **Every handshake fails**: `crypto/ecdh: use of X25519 is not allowed in FIPS 140-only mode` | Same as `on` | Same as `on` |
| boringcrypto, no `fipsonly` | Same as non-FIPS (PQ) | Same | Same | Same |
| boringcrypto + `import _ "crypto/tls/fipsonly"` | not run | P-256, P-384, P-521, no PQ | Same | Same |
| boringcrypto + `fips140=on` | Panics at start: `FIPS 140-3 mode is incompatible with GOEXPERIMENT=boringcrypto` | Same | Same | Same |

All cells Tested (e2e on Lambda, Fargate and EC2, and container builds). The TLS group policy follows the toolchain, not the module version: `GOFIPS140=v1.0.0` built with Go 1.26 offered the SecP hybrids (Tested). Module v1.0.0 holds CMVP certificate #5247; v1.26.0 was "Pending Review" in the CMVP Modules In Process List as of 2026-04-28 ([Go FIPS page](https://go.dev/doc/security/fips140); Documented). In FIPS mode a server that offers only X25519 can't be reached, whatever the PQ setting.

### H. Libraries with their own TLS settings

**Who this is.** You pass a `tls.Config` to the AWS SDK, gRPC or a database driver, often to add a private CA or a client certificate.

**What happens today.** All three pass your `tls.Config` through unchanged, PQ included. Tested with Go 1.26.11, a config holding the private CA and an EC client cert, against a Go PQ-only mTLS server that logs the group and client CN, and OpenSSL PQ-only and classical mTLS servers:

| Library | How the config was passed | Result | Same config + `CurvePreferences {X25519, P256}` | With `GODEBUG=tlsmlkem=0` |
| --- | --- | --- | --- | --- |
| aws-sdk-go-v2 v1.48.0, config v1.33.18 | `NewBuildableClient().WithTransportOptions(...)` or a plain `*http.Client` via `config.WithHTTPClient` | X25519MLKEM768, `client_cn=cli-ec`; classical fallback OK | Fails to PQ-only | Fails to PQ-only (also e2e) |
| grpc-go v1.85.0 | `credentials.NewTLS(cfg)` or `NewClientTLSFromFile` | X25519MLKEM768 | Fails | Fails |
| pgx v5.13.0 | `ConnConfig.TLSConfig`, or DSN `sslrootcert`/`sslcert`/`sslkey`; `sslnegotiation=direct` | X25519MLKEM768, `client_cn=cli-ec` | Fails | Fails |

pgx with the default `sslnegotiation=postgres` (TLS after `SSLRequest`) uses the same `tls.Config` but was not run (Unverified). Outside Go's TLS: `confluent-kafka-go` uses librdkafka with its own OpenSSL, and anything you exec (curl, git, wget) uses the image's TLS library (not tested from Go; Unverified).

**AWS SDK for Go v2 in FIPS mode** is the one library default that blocks PQ: v1.48.0's `aws/transport/http/client.go` sets `CurvePreferences` to P-256, P-384 and P-521 when FIPS mode is on, so a PQ-only server fails (Tested, also e2e). Not sure which SDK release added this. Put the approved hybrids back (Tested, also e2e: PQ-only server then succeeded):

``` go
hc := awshttp.NewBuildableClient().WithTransportOptions(func(t *http.Transport) {
    if fips140.Enabled() {
        t.TLSClientConfig.CurvePreferences = []tls.CurveID{
            tls.SecP256r1MLKEM768, tls.X25519MLKEM768, tls.CurveP256, tls.CurveP384}
    }
})
cfg, _ := config.LoadDefaultConfig(ctx, config.WithHTTPClient(hc))
```

For gRPC, pgx, go-redis, kafka-go and sarama nothing changes: pass a `tls.Config` with `ServerName` or `RootCAs` and no curves, and avoid helpers that build a config with a fixed curve list.

### I. Pinning, and HSM, PKCS#11 or KMS keys

**Who this is.** `VerifyPeerCertificate` or `VerifyConnection` with SPKI hashes; a `tls.Certificate` whose `PrivateKey` is a KMS, CloudHSM or PKCS#11 `crypto.Signer`.

**What happens today.**

- SPKI pinning in `VerifyConnection`: the right pin passed over X25519MLKEM768 and X25519; a wrong pin failed with your error (Tested 1.24.13, 1.26.11; also e2e). Key exchange doesn't touch certificates, so pins stay valid until you move to ML-DSA certificates.
- A server key behind an opaque `crypto.Signer` (only `Public` and `Sign`), RSA and EC: `Sign` was called once per handshake and X25519MLKEM768 was negotiated (Tested 1.24.13, 1.26.11). ML-KEM runs in software in `crypto/tls`; the HSM only signs. A real KMS, CloudHSM or PKCS#11 module was not tested (Unverified).

**What to change.** Nothing. **Side effects.** None.

| NLB TCP listener (passthrough) | Your Go server: everything above applies | Documented |

## Solution and automation

1. **Inventory.** `go-pq-posture.sh` over every built artifact (Lambda `bootstrap`, binaries copied out of images, EC2 binaries); `go-pq-lint.sh` over every repo; export `GODEBUG` from Lambda configurations, task definitions, pod specs and systemd units.
2. **Change.** Raise the `go` line to 1.26 and rebuild with Go 1.26+. Remove blocking settings (case F). For FIPS, native `GOFIPS140` and the AWS SDK fix (cases G, H). Where the `go` line can't move yet, `GODEBUG=tlsmlkem=1,tlssecpmlkem=1`.
3. **CI guardrails.** Fail the build on `go-pq-lint.sh` findings before compiling, then run `go-pq-posture.sh` on the built binary (Tested on the e2e build: FAIL for every classical-by-build probe, WARN for boringcrypto). The lint is a file-level heuristic: a file that mentions ML-KEM anywhere passes its `CurvePreferences` check, so review hits by hand.

## Pitfalls and rollback

| Pitfall | What happens | Evidence |
| --- | --- | --- |
| New toolchain, old `go` line | The most common miss: Go 1.27 with `go 1.23` stays classical. Check `DefaultGODEBUG`, not the toolchain | Tested |
| `CurvePreferences` set anywhere | One list without a hybrid makes that client or server classical, silently; check libraries (AWS SDK in FIPS mode) | Tested |
| `tlsmlkem=0` left set "temporarily" | On 1.24 to 1.26 it beats even an explicit hybrid list | Tested |
| FIPS on Go 1.24, or boringcrypto + `fipsonly` | No PQ at all; Go 1.25 `fips140=only` fails every handshake | Tested |
| Go 1.26 with `go 1.25` | X25519MLKEM768 works, SecP256r1MLKEM768 doesn't: the only hybrid some FIPS-oriented servers accept | Tested |
| `godebug tlssecpmlkem=1` in `go.mod` on a 1.24 or 1.25 toolchain | Build fails: `unknown godebug "tlssecpmlkem"` | Tested |
| Go 1.23 isn't "almost PQ" | Its Kyber draft (0x6399) isn't ML-KEM; PQ-only servers refuse it, and no `GODEBUG` or Lambda layer fixes it | Tested |
| Big ClientHello | ML-KEM adds about 1.2 KB, so the ClientHello spans two TCP segments; broken middleboxes time out ([tldr.fail](https://tldr.fail/)). See Network devices and egress | Documented |
| `x/crypto/pkcs12` on OpenSSL 3 PKCS#12 files | Fails at start-up with `unknown digest algorithm`; use go-pkcs12 | Tested |
| AWS CA bundle with your own `*http.Client` | `AWS_CA_BUNDLE` or `WithCustomCABundle` fails at config load | Tested |
| `SSL_CERT_FILE` with only a private CA | Public endpoints then fail with `unknown authority`: it replaces the system bundle | Documented |
| mTLS errors in TLS 1.3 | A missing client cert shows as `certificate required` on the first read, not on dial | Tested |
| RSA listed before EC | Default clients get RSA; not a PQ issue, but surprising during certificate moves | Tested |

**Rollback**, fastest first; no code change needed (Tested in e2e: `GODEBUG=tlsmlkem=0,tlssecpmlkem=0` on a Go 1.26 build turned it classical):

1. Set `GODEBUG=tlsmlkem=0,tlssecpmlkem=0` in the function, task, pod or unit environment, then redeploy or restart.
2. Rebuild with `godebug tlsmlkem=0` in `go.mod`.
3. Redeploy the previous artifact.

Record any rollback as a temporary exception with an owner and an end date, and remove the override once the peer is fixed.

`cmd/client/main.go` (HTTP and AWS SDK client, FIPS-safe)

``` go
//go:debug tlsmlkem=1
package main

import (
    "context"
    "crypto/fips140"
    "crypto/tls"
    "log"
    "net/http"
    "time"

    awshttp "github.com/aws/aws-sdk-go-v2/aws/transport/http"
    "github.com/aws/aws-sdk-go-v2/config"
    "github.com/aws/aws-sdk-go-v2/service/sts"
)

// The //go:debug line is optional: needed only while go.mod says go < 1.24.

func httpClient() *http.Client {
    tr := http.DefaultTransport.(*http.Transport).Clone()
    tr.TLSClientConfig = &tls.Config{MinVersion: tls.VersionTLS12} // no CurvePreferences
    return &http.Client{Transport: tr, Timeout: 30 * time.Second}
}

func awsHTTPClient() *awshttp.BuildableClient {
    return awshttp.NewBuildableClient().WithTransportOptions(func(t *http.Transport) {
        if fips140.Enabled() {
            // aws-sdk-go-v2 v1.48.0 forces P-256/384/521 in FIPS mode; keep the approved hybrids.
            t.TLSClientConfig.CurvePreferences = []tls.CurveID{
                tls.SecP256r1MLKEM768, tls.X25519MLKEM768, tls.CurveP256, tls.CurveP384}
        }
    })
}

func main() {
    ctx := context.Background()
    cfg, err := config.LoadDefaultConfig(ctx, config.WithHTTPClient(awsHTTPClient()))
    if err != nil {
        log.Fatal(err)
    }
    out, err := sts.NewFromConfig(cfg).GetCallerIdentity(ctx, &sts.GetCallerIdentityInput{})
    if err != nil {
        log.Fatal(err)
    }
    log.Printf("caller=%s", *out.Arn)

    resp, err := httpClient().Get("https://api.internal.example.com/health")
    if err != nil {
        log.Fatal(err)
    }
    defer resp.Body.Close()
    log.Printf("status=%d tls_group=%v", resp.StatusCode, resp.TLS.CurveID)
}
```

`cmd/server/main.go` (HTTPS and gRPC server that logs the group)

``` go
package main

import (
    "context"
    "crypto/tls"
    "log"
    "net"
    "net/http"
    "os"

    "google.golang.org/grpc"
    "google.golang.org/grpc/credentials"
    "google.golang.org/grpc/health"
    healthpb "google.golang.org/grpc/health/grpc_health_v1"
    "google.golang.org/grpc/peer"
)

func tlsConfig() *tls.Config {
    cert, err := tls.LoadX509KeyPair("/etc/tls/tls.crt", "/etc/tls/tls.key")
    if err != nil {
        log.Fatal(err)
    }
    cfg := &tls.Config{Certificates: []tls.Certificate{cert}, MinVersion: tls.VersionTLS12}
    if os.Getenv("TLS_PQ_ONLY") == "1" { // enforcement mode, after every client is PQ
        cfg.MinVersion = tls.VersionTLS13
        cfg.CurvePreferences = []tls.CurveID{tls.X25519MLKEM768, tls.SecP256r1MLKEM768}
    }
    return cfg
}

func main() {
```

`go-pq-posture.sh` (CI gate and host or image scan)

``` sh
#!/bin/sh
# Usage: go-pq-posture.sh <dir-with-go-binaries>   (needs a Go toolchain on PATH)
# Fails if any Go binary is classical by build. Runtime GODEBUG must be checked separately.
rc=0
for f in $(find "$1" -type f -perm -u+x); do
  info=$(go version -m "$f" 2>/dev/null) || continue      # not a Go binary
  ver=$(echo "$info" | head -1 | sed -E 's/.*go1\.([0-9]+).*/\1/')
  dbg=$(echo "$info" | grep -o 'DefaultGODEBUG=[^ ]*')
  exp=$(echo "$info" | grep -o 'GOEXPERIMENT=[^ ]*')
  if [ "$ver" -lt 24 ]; then echo "FAIL $f go1.$ver: no ML-KEM"; rc=1
  elif echo "$dbg" | grep -q 'tlsmlkem=0'; then echo "FAIL $f go1.$ver: tlsmlkem=0 (go.mod go line < 1.24)"; rc=1
  elif echo "$exp" | grep -q boringcrypto; then echo "WARN $f boringcrypto: check for crypto/tls/fipsonly"
  elif echo "$dbg" | grep -q 'fips140=on' && [ "$ver" -lt 25 ]; then echo "FAIL $f go1.$ver FIPS: no PQ before 1.25"; rc=1
  else echo "OK   $f go1.$ver $dbg"; fi
done
exit $rc
```

`cases/main.go` (cases C, D, E, F, standard library only; build with a go.mod of `module cases` and the `go` line under test)

```go
// cases: Go TLS case tests C, D, E, F with the standard library only.
// Compiles on Go 1.23+ (no tls.X25519MLKEM768 constant, no ConnectionState.CurveID needed).
//
//	cases client-default   D: nil RootCAs (system roots; runner sets SSL_CERT_FILE / SSL_CERT_DIR)
//	cases client           D, E, F client cases against the OpenSSL servers
//	cases server           C, E, F server cases on :9443..:9455 (probed with openssl s_client)
package main

import (
	"crypto/tls"
	"crypto/x509"
	"encoding/pem"
	"fmt"
	"log"
	"net"
	"os"
	"strings"
	"time"
)

const x25519mlkem768 = tls.CurveID(4588) // tls.X25519MLKEM768 from Go 1.24

var extraModes = map[string]func(){}

func p(f string) string { return "/certs/" + f }

func must[T any](v T, err error) T {
	if err != nil {
		log.Fatal(err)
	}
	return v
}

func caPool() *x509.CertPool {
	pool := x509.NewCertPool()
	if !pool.AppendCertsFromPEM(must(os.ReadFile(p("ca.pem")))) {
		log.Fatal("no CA")
	}
	return pool
}

func pair(name string) tls.Certificate { return must(tls.LoadX509KeyPair(p(name+".pem"), p(name+".key"))) }

// Targets: OpenSSL 3.5 s_server instances started by the runner.
const (
	pqOnly       = "localhost:8443" // -tls1_3 -groups X25519MLKEM768
	classical    = "localhost:8444" // -groups X25519 (TLS 1.2 and 1.3)
	pqOnlyMTLS   = "localhost:8445" // PQ-only + -Verify 1 -CAfile ca.pem
	classicalMTL = "localhost:8446" // X25519 + -Verify 1 -CAfile ca.pem
)

func try(caseID, label, addr string, cfg *tls.Config) {
	if cfg.ServerName == "" {
		cfg.ServerName = "localhost"
	}
	c, err := tls.DialWithDialer(&net.Dialer{Timeout: 5 * time.Second}, "tcp", addr, cfg)
	if err != nil {
		e := err.Error()
		if len(e) > 110 {
			e = e[:110]
		}
		fmt.Printf("%s | %-44s | %-15s | FAIL | %s\n", caseID, label, addr, e)
		return
	}
	defer c.Close()
	// mTLS failures surface on first read in TLS 1.3, so read the -www reply.
	c.SetDeadline(time.Now().Add(5 * time.Second))
	fmt.Fprintf(c, "GET / HTTP/1.0\r\n\r\n")
	buf := make([]byte, 64)
	_, rerr := c.Read(buf)
	cs := c.ConnectionState()
	res := "OK  "
	extra := ""
	if rerr != nil && !strings.Contains(rerr.Error(), "EOF") {
		res, extra = "FAIL", " read: "+rerr.Error()
	}
	fmt.Printf("%s | %-44s | %-15s | %s | %s group=%s%s\n", caseID, label, addr, res, ver(cs.Version), curveName(cs), extra)
}

func ver(v uint16) string {
	switch v {
	case tls.VersionTLS13:
		return "TLS1.3"
	case tls.VersionTLS12:
		return "TLS1.2"
	}
	return fmt.Sprintf("%x", v)
}

func clientDefault() {
	label := os.Getenv("TRUST_LABEL")
	for _, a := range []string{pqOnly, classical} {
		try("D", "default RootCAs ("+label+")", a, &tls.Config{})
	}
}

func clientCases() {
	both := []string{pqOnly, classical}
	// D: custom trust
	for _, a := range both {
		pool, err := x509.SystemCertPool()
		if err != nil {
			pool = x509.NewCertPool()
		}
		pool.AppendCertsFromPEM(must(os.ReadFile(p("ca.pem"))))
		try("D", "SystemCertPool()+AppendCertsFromPEM(ca)", a, &tls.Config{RootCAs: pool})
		try("D", "RootCAs = NewCertPool with private CA only", a, &tls.Config{RootCAs: caPool()})
		try("D", "RootCAs = empty pool (negative)", a, &tls.Config{RootCAs: x509.NewCertPool()})
	}
	// E: mutual TLS
	rsaCli, ecCli := pair("cli-rsa"), pair("cli-ec")
	for _, a := range []string{pqOnlyMTLS, classicalMTL} {
		try("E", "Certificates=[client RSA]", a, &tls.Config{RootCAs: caPool(), Certificates: []tls.Certificate{rsaCli}})
		try("E", "GetClientCertificate -> client EC", a, &tls.Config{RootCAs: caPool(),
			GetClientCertificate: func(*tls.CertificateRequestInfo) (*tls.Certificate, error) { return &ecCli, nil }})
		try("E", "no client cert (negative)", a, &tls.Config{RootCAs: caPool()})
	}
	// F: explicit settings
	for _, a := range both {
		try("F", "CurvePreferences={X25519,P256}", a, &tls.Config{RootCAs: caPool(),
			CurvePreferences: []tls.CurveID{tls.X25519, tls.CurveP256}})
		try("F", "CurvePreferences={X25519MLKEM768,X25519,P256}", a, &tls.Config{RootCAs: caPool(),
			CurvePreferences: []tls.CurveID{x25519mlkem768, tls.X25519, tls.CurveP256}})
		try("F", "MaxVersion=TLS1.2", a, &tls.Config{RootCAs: caPool(), MaxVersion: tls.VersionTLS12})
		try("F", "MinVersion=TLS1.3", a, &tls.Config{RootCAs: caPool(), MinVersion: tls.VersionTLS13})
		try("F", "CipherSuites=2 ECDHE-GCM (TLS1.2 list)", a, &tls.Config{RootCAs: caPool(),
			CipherSuites: []uint16{tls.TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256, tls.TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256}})
	}
}

// ---------- server side ----------

func serve(port int, label string, cfg *tls.Config) {
	ln, err := tls.Listen("tcp", fmt.Sprintf(":%d", port), cfg)
	if err != nil {
		log.Printf("port=%d case=%q LISTEN-ERROR %v", port, label, err)
		return
	}
	go func() {
		for {
			c, err := ln.Accept()
			if err != nil {
				return
			}
			go func(c net.Conn) {
				defer c.Close()
				tc := c.(*tls.Conn)
				tc.SetDeadline(time.Now().Add(5 * time.Second))
				if err := tc.Handshake(); err != nil {
					log.Printf("port=%d case=%q handshake_error=%v", port, label, err)
					return
				}

				}

			}(c)
		}
	}()
}

// decryptLegacyPEM handles only RFC 1423 "Proc-Type: 4,ENCRYPTED" keys (deprecated API, still in stdlib).
func decryptLegacyPEM(keyFile, pass string) []byte {
	block, _ := pem.Decode(must(os.ReadFile(keyFile)))
	if block == nil || !x509.IsEncryptedPEMBlock(block) { //nolint:staticcheck
		log.Fatalf("%s: not a legacy encrypted PEM block", keyFile)
	}
	der := must(x509.DecryptPEMBlock(block, []byte(pass))) //nolint:staticcheck
	return pem.EncodeToMemory(&pem.Block{Type: block.Type, Bytes: der})
}
```

```go
// opaqueSigner hides the concrete key type, like a KMS or PKCS#11 signer: only Public() and Sign().
type opaqueSigner struct {
	inner crypto.Signer
	calls atomic.Int32
}

func (s *opaqueSigner) Public() crypto.PublicKey { return s.inner.Public() }

	n := s.calls.Add(1)

func spkiPin(file string) []byte {
	c := pair(file)
	leaf, err := x509.ParseCertificate(c.Certificate[0])
	if err != nil {
		log.Fatal(err)
	}
	h := sha256.Sum256(leaf.RawSubjectPublicKeyInfo)
	return h[:]
}

func pinned(pin []byte) *tls.Config {
	return &tls.Config{RootCAs: caPool(), VerifyConnection: func(cs tls.ConnectionState) error {
		h := sha256.Sum256(cs.PeerCertificates[0].RawSubjectPublicKeyInfo)
		if !bytes.Equal(h[:], pin) {
			return errors.New("SPKI pin mismatch")
		}
		return nil
	}}
}
```

```go
func serve(port int, label string, cfg *tls.Config) {
	ln := must(tls.Listen("tcp", fmt.Sprintf(":%d", port), cfg))
	go func() {
		for {
			c, err := ln.Accept()
			if err != nil {
				return
			}
			go func(tc *tls.Conn) {
				defer tc.Close()
				tc.SetDeadline(time.Now().Add(5 * time.Second))
				if err := tc.Handshake(); err != nil {
					log.Printf("port=%d case=%q handshake_error=%v", port, label, err)
					return
				}
				cs := tc.ConnectionState()
				log.Printf("port=%d case=%q group=%s leaf=%s", port, label, cs.CurveID, cfg.Certificates[0].Leaf.Subject.CommonName)
				tc.Write([]byte("HTTP/1.0 200 OK\r\n\r\nok\n"))
			}(c.(*tls.Conn))
		}
	}()
}

func certFrom(key any, leaf *x509.Certificate, chain []*x509.Certificate) tls.Certificate {
	c := tls.Certificate{PrivateKey: key, Leaf: leaf, Certificate: [][]byte{leaf.Raw}}
	for _, ca := range chain {
		c.Certificate = append(c.Certificate, ca.Raw)
	}
	return c
}

func verdict(err error) string {
	if err == nil {
		return "TLS-OK"
	}
	s := err.Error()
	if len(s) > 150 {
		s = s[len(s)-150:]
	}
	if strings.Contains(s, "tls:") || strings.Contains(s, "handshake") || strings.Contains(s, "remote error") || strings.Contains(s, "x509:") {
		return "TLS-FAIL: " + s
	}
	return "TLS-OK, then protocol error: " + s
}

func short() context.Context { c, _ := context.WithTimeout(context.Background(), 6*time.Second); return c }

func awsCall(hc config.HTTPClient, endpoint string, extra ...func(*config.LoadOptions) error) error {
	opts := []func(*config.LoadOptions) error{config.WithRegion("us-east-1"),
		config.WithCredentialsProvider(credentials.NewStaticCredentialsProvider("AKIDEXAMPLE", "secret", "")),
		config.WithRetryMaxAttempts(1)}
	if hc != nil {
		opts = append(opts, config.WithHTTPClient(hc))
	}
	opts = append(opts, extra...)
	ac, err := config.LoadDefaultConfig(context.Background(), opts...)
	if err != nil {
		return fmt.Errorf("config: %w", err)
	}
	cl := sts.NewFromConfig(ac, func(o *sts.Options) { o.BaseEndpoint = aws.String(endpoint) })
	_, err = cl.GetCallerIdentity(short(), &sts.GetCallerIdentityInput{})
	return err
}

func pgxCall(dsn string, cfg *tls.Config) error {
	pc, err := pgx.ParseConfig(dsn)
	if err != nil {
		return fmt.Errorf("parse: %w", err)
	}
	if cfg != nil {
		cfg.ServerName = pc.Host
		pc.TLSConfig = cfg
		pc.Fallbacks = nil
	}
	c, err := pgx.ConnectConfig(short(), pc)
	if c != nil {
		c.Close(context.Background())
	}
	return err
}

func grpcCall(addr string, creds grpccreds.TransportCredentials) error {
	conn, err := grpc.NewClient(addr, grpc.WithTransportCredentials(creds))
	if err != nil {
		return err
	}
	defer conn.Close()
	_, err = healthpb.NewHealthClient(conn).Check(short(), &healthpb.HealthCheckRequest{})
	return err
}
```
