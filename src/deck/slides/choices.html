KEY MESSAGE: We keep the change small, reversible and provable, so it can go everywhere, and certificates follow on their own track. • Key exchange first: no certificate re-issue for the ML-KEM rollout. ML-DSA follows by use case; it starts now only for device roots and long-lived signatures. • Hybrid, never PQ-only: anything that can’t do PQ still connects, so nothing breaks on the day we switch. • The platform ships the fix in the shared build template; app teams release it. Rollback is removing one file or one variable. • Guardrails start in warn mode (about 30 days first, per the plan’s risk table) so teams aren’t blocked by a rule we got wrong. • And a workload is only done when a log shows X25519MLKEM768, not when the change merges. • For ML-DSA certificates, two certificates on one server, never ML-DSA alone: clients that can’t use it get ECDSA. The one-certificate composite form can’t be negotiated in TLS yet.
