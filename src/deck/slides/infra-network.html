Post-quantum TLS on AWS · 21 · Guide: Infrastructure tabs; AWS support checked 2026-11-16

KEY MESSAGE: Network and data services are where AWS blocks the most; we record those legs as exceptions and protect what we can around them. • Egress: an egress proxy like Squid or Envoy carries PQ for workloads that can’t upgrade yet. Zeek on VPC traffic mirroring shows which group each connection used. • Risk: Network Firewall TLS inspection terminates and re-originates TLS, so inspected traffic loses PQ. AWS VPN has no PQ option. • IoT Core has no PQ policy. The real risk is device lifetime: the TLS stack in firmware we ship now is what those devices use for years. • Mesh: Linkerd 2.19 is PQ by default; Istio 1.27 is opt-in, and its pqc compliance mode is PQ-only, which breaks classical peers. Turn it on last. • Databases: RDS and Aurora depend on the engine version, and the client driver must support the group. RDS Proxy, ElastiCache, MSK and OpenSearch have no option yet. • These rows are from vendor and AWS documentation; mesh, database and IoT were not run in the emulator.
