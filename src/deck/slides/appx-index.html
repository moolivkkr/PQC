Appendix · how the tests work

One suite, real deployments, graded per handshake

Deploy

Real compute, emulated AWS

LocalStack Pro runs each case as a real Lambda zip, layer or image, ECS Fargate or EC2-launch task, or EC2 instance from AL2023 and AL2 AMIs.

Connect

Eight targets per case

PQ hybrid, PQ-only, mTLS, EC certificate, TLS 1.2, and three ML-DSA targets: dual certificate, ML-DSA only, ML-DSA client certificate.

Grade

Observer vs expectation

A TLS observer records the group and signature each handshake used. A case passes only if that matches the result the guide predicts.

KEY MESSAGE: Every number in this deck comes from one test suite that deploys real workloads and checks each handshake against what the guide predicts. • LocalStack Pro emulates the AWS APIs, but the code runs for real: Lambda functions in the AWS base images, ECS tasks, and EC2 instances booted from Amazon Linux AMIs. • Each case connects to eight targets. Five cover key exchange; three cover ML-DSA certificates. • The observer is a Go TLS server that logs the group each client offered and used. The ML-DSA fixture is a Python 3.15 server that also logs which certificate and signature were used. • The expected result per case is written from the guide before the run; a case only passes when reality matches it, so the guide is what’s being tested. • Not covered: real AWS accounts, x86_64, EKS, and the ALB/NLB listener leg. Those are Phase 0. • The next slides list the cases per language with links to the code.
