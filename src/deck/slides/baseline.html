The baseline

What changes, and how we tested it

Today

Classical key exchange

  • X25519 or ECDHE agrees the session key
  • Every TLS 1.2 connection is classical
  • What most of our workloads negotiate now

Target

Hybrid X25519MLKEM768, TLS 1.3

  • ML-KEM plus X25519: at least as strong as today
  • Only the key agreement changes
  • Certificates, keystores and CA bundles stay

Graded, not assumed: each workload connects to a TLS observer that records the groups offered and negotiated, including a listener that accepts only X25519MLKEM768. Every claim in the guide is a test case.

KEY MESSAGE: We change one thing, how the session key is agreed, and we test it against a server that refuses anything else. • Orange is today: classical X25519, and anything on TLS 1.2. • Blue is the target: the hybrid group X25519MLKEM768. It combines ML-KEM with X25519, so it is never weaker than what we run now. • Certificates do not change. We tested our own server certificates, private CA trust and mutual TLS with the fix in place. • The test method matters: an observer logs exactly what each client offered and negotiated, and a PQ-only listener fails anything that is not PQ. • Post-quantum certificates (ML-DSA) are a separate, later step.
