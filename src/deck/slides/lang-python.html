KEY MESSAGE: Python follows the OpenSSL it is linked to, so the fix lives wherever OpenSSL is configured: the package on Lambda, the image on containers, the host on EC2. • Lambda 3.12 to 3.14 run on AL2023, whose crypto policy leaves ML-KEM out. One config file, shipped in the pq-tls layer or the package, turns it on. • Lambda 3.9 to 3.11 run on Amazon Linux 2 with OpenSSL 1.1.1: no ML-KEM at all. Upgrade; the shim is a bridge for requests and boto3 only. • Containers: Debian 13 and Alpine images are PQ out of the box; AL2023 images need the env var or DEFAULT:PQ; Debian 12 needs a new base. • EC2: the same file per service through systemd, or DEFAULT:PQ for the whole host through SSM. Amazon Linux 2 hosts must migrate. • Bundled-TLS libraries like grpcio and awscrt are already PQ everywhere. • EKS not run in the emulator; same images as ECS.
