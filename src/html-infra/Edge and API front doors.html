Edge and API front doors

What decides PQ here

Each managed front door terminates TLS with its own stack, so the service and the policy you pick decide the client-facing leg. CloudFront and Cognito custom domains offer PQ on TLS 1.3 already. API Gateway REST needs an opt-in SecurityPolicy_*_PQ_* policy plus an endpoint access mode. HTTP, WebSocket and edge-optimized APIs have no PQ policy. The upstream legs are classical today: CloudFront to origin, and API Gateway to its integrations. Global Accelerator does not terminate TLS, so the client and your endpoint decide.

Endpoint access mode. Every SecurityPolicy_* policy needs BASIC or STRICT. STRICT rejects requests whose SNI and Host do not match or that arrive from another endpoint type. Move to the PQ policy with BASIC, check access logs, then switch to STRICT. Changes take about 15 minutes (API Gateway security policies, Documented).

mTLS on API Gateway custom domains. No statement on combining mTLS with the PQ policies was found. Not confirmed; test before relying on it.

No TLS 1.3-only PQ policy on API Gateway. SecurityPolicy_TLS13_1_3_2025_09 has no PQ in its name and is not listed as PQ. To force TLS 1.3 with PQ, put CloudFront (TLSv1.3_2025) or an ALB (ELBSecurityPolicy-TLS13-1-3-PQ-2025-09) in front.

The CloudFront-Viewer-TLS-Details header replaces the earlier "third-party report" in this tab: AWS now documents it. It can go in an origin request policy, not a cache policy. Log it at the origin, for example nginx:

log_format cf_tls '$remote_addr [$time_local] "$request" $status cf_tls=$http_cloudfront_viewer_tls_details';
access_log /var/log/nginx/cf_tls.log cf_tls;

Pitfalls, enforcement and rollback

  • STRICT endpoint access mode breaks VPC-endpoint access to a public custom domain, private APIs called without a custom domain or private DNS, and domain sharding. Use BASIC there.

  • Moving from STRICT back to BASIC makes the endpoint unavailable for about 15 minutes. Moving from an enhanced policy back to a legacy one needs the endpoint access mode set to "". An API on TLS_1_0 cannot be moved to TLS_1_2. (Documented)

  • A custom domain's policy wins over its mapped API's policy for calls through that domain. Disable or align the default execute-api endpoint, or clients can bypass the PQ policy.

  • HTTP and WebSocket APIs cannot be made PQ. Front them with CloudFront or a PQ ALB, or migrate to a Regional REST API.

  • CloudFront's origin leg and API Gateway's integration leg stay classical: record them as exceptions rather than claiming end-to-end PQ.

  • Enforcement. No IAM condition key for API Gateway or CloudFront TLS policies was found. Enforce in the pipeline (policy fields in templates) and with Config rules. Prowler has API Gateway PQ checks (its default allowlist looked wrong in review).

  • Rollback. Set the previous SecurityPolicy in IaC and deploy (about 15 minutes on API Gateway). CloudFront: set the previous MinimumProtocolVersion. Transfer Family: set the previous SecurityPolicyName.

# --- CloudFront: forward the viewer TLS details so the origin can log keyExchange.
resource "aws_cloudfront_origin_request_policy" "tls_details" {
  name = "forward-viewer-tls-details"
  cookies_config { cookie_behavior = "none" }
  query_strings_config { query_string_behavior = "all" }
  headers_config {
    header_behavior = "allViewerAndWhitelistCloudFront"
    headers {
      items = ["CloudFront-Viewer-TLS-Details", "CloudFront-Viewer-JA4-Fingerprint"]
    }
  }
}

data "aws_cloudfront_cache_policy" "optimized" {
  name = "Managed-CachingOptimized"
}

resource "aws_cloudfront_distribution" "site" {
  enabled = true
  aliases = ["www.example.com"]

  origin {
    origin_id   = "alb"
    domain_name = var.origin_domain
    custom_origin_config {
      http_port              = 80
      https_port             = 443
      origin_protocol_policy = "https-only"
      # Highest value CloudFront offers to origins; the origin leg is classical either way.
      origin_ssl_protocols = ["TLSv1.2"]
    }
  }

  default_cache_behavior {
    target_origin_id         = "alb"
    viewer_protocol_policy   = "redirect-to-https"
    allowed_methods          = ["GET", "HEAD", "OPTIONS"]
    cached_methods           = ["GET", "HEAD"]
    cache_policy_id          = data.aws_cloudfront_cache_policy.optimized.id
    origin_request_policy_id = aws_cloudfront_origin_request_policy.tls_details.id
  }

  viewer_certificate {
    acm_certificate_arn = var.cf_certificate_arn
    ssl_support_method  = "sni-only"
    # PQ is offered on every policy for TLS 1.3 viewers. Move to TLSv1.3_2025 to drop TLS 1.2.
    minimum_protocol_version = "TLSv1.2_2021"
  }

  restrictions {
    geo_restriction { restriction_type = "none" }
  }
}
