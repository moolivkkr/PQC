Load balancers: ALB, NLB, GWLB, Classic

What decides PQ here

The load balancer's security policy decides the client-facing leg. Only policies with PQ in the name offer X25519MLKEM768, SecP256r1MLKEM768 and SecP384r1MLKEM1024, and only on TLS 1.3. The console defaults to a PQ policy; the CLI, CloudFormation, CDK, Terraform and the AWS Load Balancer Controller default to ELBSecurityPolicy-2016-08, which is classical. On the target leg the load balancer is the TLS client: AWS picks its backend policy from your listener policy, and the target's own TLS stack decides whether that hop is PQ. Sources: ALB policies, NLB policies (Documented, read 2026-11-14).

Client side: the load balancer's connection to targets

The load balancer is the TLS client on the target leg, and you cannot choose its policy. AWS uses ELBSecurityPolicy-TLS13-1-0-PQ-2025-09 if any listener uses a PQ policy, ELBSecurityPolicy-TLS13-1-0-FIPS-PQ-2025-09 for a FIPS PQ listener, and an RFC 9151 listener overrides both (Documented). The backend policy offers ML-KEM groups, so the hop is PQ only when the target accepts one. AWS does not log the group negotiated to the target.

Packaging and rollout from TLS 1.2+1.3 to 1.3-only

Organisation guardrailSCP on elasticloadbalancing:SecurityPolicyiac/lb/scp-elb-pq.json
DetectionAthena tables and queriesiac/lb/athena.sql

  1. Turn on ALB connection logs and NLB access logs (both off by default) and create the Athena tables.

  2. Move every HTTPS and TLS listener of a load balancer to ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09 in one change. Classical and TLS 1.2 clients still connect.

  3. Watch Q1 (key-exchange mix) and Q2 (classical client IPs); Q4 adds user agents through conn_trace_id. Hand the client list to app owners (language tabs).

  4. When Q3 (TLS 1.2 connections) is zero for the agreed window, move the listener to ELBSecurityPolicy-TLS13-1-3-PQ-2025-09. That ends TLS 1.2 but still allows classical TLS 1.3 key exchange.

  5. No ELB policy refuses classical TLS 1.3 key exchange. A PQ-only gate needs a server you control (Web servers and proxies).

  6. Put remaining TLS 1.2 callers on a separate load balancer or hostname and record them as exceptions.

Enforce, pitfalls and rollback

SCP (full file below). The condition key elasticloadbalancing:SecurityPolicy applies to CreateListener and ModifyListener (ALB, NLB) and to CreateLoadBalancerPolicy and SetLoadBalancerPoliciesOfListener (Classic). It does not apply to CreateLoadBalancer (ELB IAM page, Documented). This corrects the earlier version of this tab. AWS's example uses ForAnyValue:StringEquals in an Allow; the Deny below uses ForAnyValue:StringNotEquals, plus a Null check that catches HTTPS/TLS listeners created without an explicit policy (they would get ELBSecurityPolicy-2016-08). The deny logic was not tested against AWS (no credentials here): attach it to a sandbox OU first. Unverified.

SCP stages. The two allowlists in this document are stages, not a conflict. The org baseline on Enforcement and guardrails allows all eleven non-TLS-1.0 PQ ELB policies while teams migrate. The SCP below narrows that to four: ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09, ELBSecurityPolicy-TLS13-1-3-PQ-2025-09 and their FIPS variants. Once a listener's TLS 1.2 traffic reaches zero, drop the two TLS13-1-2-Res entries so only the TLS 1.3-only PQ policies remain.

{"Sid": "DenyNonPqElbListenerPolicy", "Effect": "Deny",
 "Action": ["elasticloadbalancing:CreateListener", "elasticloadbalancing:ModifyListener"],
 "Resource": "*",
 "Condition": {"ForAnyValue:StringNotEquals": {"elasticloadbalancing:SecurityPolicy": [
   "ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09", "ELBSecurityPolicy-TLS13-1-2-Res-FIPS-PQ-2025-09",
   "ELBSecurityPolicy-TLS13-1-3-PQ-2025-09", "ELBSecurityPolicy-TLS13-1-3-FIPS-PQ-2025-09"]}}}

Pipeline. cfn-guard, OPA/conftest or Checkov custom rules on SslPolicy / ssl_policy / the LBC annotations. No built-in Checkov, tfsec or Trivy PQ rule was found. Remediation. The Config rule above, with SSM Automation calling aws elbv2 modify-listener if you allow fixes outside the pipeline.

Pitfalls

  • IaC that omits the policy gets ELBSecurityPolicy-2016-08, although the console shows a PQ default. The Load Balancer Controller behaves the same.

  • IngressClassParams.spec.sslPolicy silently overrides an Ingress ssl-policy annotation.

  • The X25519MLKEM768 key share adds about 1.2 KB, so the ClientHello often spans two packets. Old middleboxes in front of clients can drop it. Test partner networks before the 1.3-only move.

  • The backend policy follows "any listener". A search snippet claims PQ and non-PQ policies are "not compatible" on listeners of one load balancer; this is not on the policy pages read on 2026-11-14, so it is not confirmed. Move all listeners of a load balancer together anyway.

  • Policy changes are online, but clients with pinned cipher lists can fail after a 1.3-only move.

Rollback. aws elbv2 modify-listener --listener-arn ARN --ssl-policy ELBSecurityPolicy-TLS13-1-2-Res-PQ-2025-09 (from 1.3-only), or back to the previous policy. Exempt the break-glass role in the SCP so it can do this. Make the same change in IaC so the next deploy does not undo it.

-- ALB connection logs: 15 fields (tls_keyexchange = field 13). AWS's published Athena DDL
-- stops at conn_trace_id; this one adds tls_keyexchange, elb and ip_address, and accepts
-- an unquoted "-" in leaf_client_cert_subject (listeners without mTLS).
CREATE EXTERNAL TABLE IF NOT EXISTS alb_connection_logs (
  time string, client_ip string, client_port int, listener_port int,
  tls_protocol string, tls_cipher string, tls_handshake_latency double,
  leaf_client_cert_subject string, leaf_client_cert_validity string,
  leaf_client_cert_serial_number string, tls_verify_status string,
  conn_trace_id string, tls_keyexchange string, elb string, ip_address string
)
ROW FORMAT SERDE 'org.apache.hadoop.hive.serde2.RegexSerDe'
WITH SERDEPROPERTIES (
  'serialization.format' = '1',
  'input.regex' = '^([^ ]*) ([^ ]*) ([0-9]*) ([0-9]*) ([A-Za-z0-9.-]*) ([^ ]*) ([-.0-9]*) (\"[^\"]*\"|[^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ([^ ]*) ?([^ ]*)? ?([^ ]*)? ?([^ ]*)?(?: .*)?$'
)
LOCATION 's3://LOG_BUCKET/alb-conn/AWSLogs/ACCOUNT_ID/elasticloadbalancing/REGION/';

-- Q1. Key-exchange mix per ALB, last 7 days.
SELECT elb, tls_protocol, tls_keyexchange, count(*) AS connections,
       round(100.0 * count(*) / sum(count(*)) OVER (PARTITION BY elb), 2) AS pct
FROM alb_connection_logs
WHERE tls_protocol <> '-'
  AND from_iso8601_timestamp(time) > current_timestamp - interval '7' day
GROUP BY elb, tls_protocol, tls_keyexchange
ORDER BY elb, connections DESC;

-- Q2. Classical clients on an ALB: top client IPs without ML-KEM.
SELECT client_ip, tls_protocol, tls_keyexchange, count(*) AS connections
FROM alb_connection_logs
WHERE tls_protocol <> '-'
  AND lower(tls_keyexchange) NOT LIKE '%mlkem%'
  AND from_iso8601_timestamp(time) > current_timestamp - interval '7' day
GROUP BY client_ip, tls_protocol, tls_keyexchange
ORDER BY connections DESC
LIMIT 100;

-- Q3. Gate for the TLS 1.3-only move: TLS 1.2 or older per listener port.
SELECT elb, listener_port, tls_protocol, count(*) AS connections
FROM alb_connection_logs
WHERE tls_protocol IN ('TLSv1', 'TLSv1.1', 'TLSv1.2')
  AND from_iso8601_timestamp(time) > current_timestamp - interval '30' day
GROUP BY elb, listener_port, tls_protocol
ORDER BY connections DESC;

-- Q4. User agents of classical connections (ALB access logs carry the same conn_trace_id).
-- Assumes an alb_access_logs table with a conn_trace_id column.
SELECT a.user_agent, c.tls_keyexchange, count(*) AS requests
FROM alb_connection_logs c
JOIN alb_access_logs a ON a.conn_trace_id = c.conn_trace_id
WHERE lower(c.tls_keyexchange) NOT LIKE '%mlkem%' AND c.tls_protocol <> '-'
GROUP BY a.user_agent, c.tls_keyexchange
ORDER BY requests DESC
LIMIT 50;

-- Q5. NLB TLS listeners: key-exchange mix, then classical clients by SNI.
SELECT elb, domain_name, tls_protocol_version, tls_keyexchange, count(*) AS connections
FROM nlb_tls_logs
WHERE tls_protocol_version <> '-'
GROUP BY elb, domain_name, tls_protocol_version, tls_keyexchange
ORDER BY connections DESC;

SELECT client_ip, domain_name, tls_protocol_version, tls_keyexchange, count(*) AS connections
FROM nlb_tls_logs
WHERE tls_protocol_version <> '-' AND lower(tls_keyexchange) NOT LIKE '%mlkem%'
GROUP BY client_ip, domain_name, tls_protocol_version, tls_keyexchange
ORDER BY connections DESC
LIMIT 100;
