Web servers, reverse proxies and app servers (self-managed)

Every OpenSSL 3.5, Go 1.24+ and JDK 25 server tested here negotiates X25519MLKEM768 on both legs with one or two lines of config; Envoy and anything under the Amazon Linux 2023 crypto policy stay classical until you set the group list. 110 checks across 20 server configurations, run 2026-11-14.

What decides PQ here

The TLS library linked into the server binary decides, separately for each leg. Inbound (client to server) uses the listener's group list. Upstream (server to backend: proxy_pass, ProxyPass, HAProxy server lines, Envoy clusters) uses the proxy's client-side group list.

OpenSSL 3.5 puts X25519MLKEM768 first in its built-in default, so nginx, Apache httpd, HAProxy and Tomcat's OpenSSL connector are PQ on both legs with no directive at all, unless a system policy overrides it (Amazon Linux 2023 and other RHEL-family crypto-policies). Envoy (BoringSSL) before 1.40 defaults to X25519 and P-256 and must be told; from 1.40.0 X25519MLKEM768 is in the default list on both legs (Tested on 1.40.2, 2026-11-16: with no ecdh_curves, a PQ-only client negotiated X25519MLKEM768 and a PQ-only backend returned 200). Caddy and Traefik use Go's crypto/tls, PQ by default since Go 1.24. Tomcat's JSSE connector follows the JDK (Java); IIS follows Windows SChannel (.NET, Hosts and OS).

Client side (upstream leg)

The upstream leg is the one most often missed: a PQ listener in front of a classical proxy_pass leaves the backend hop exposed. Test it against a PQ-only backend (Verify).

  • nginx (1.19.4+ for proxy_ssl_conf_command). Without it nginx uses OpenSSL's default list: PQ on OpenSSL 3.5, but not under the AL2023 policy (Tested: HTTP 502 to a PQ-only backend).

    location /api/ {
    proxy_pass https://backend:8443/;
    proxy_ssl_protocols TLSv1.3;
    proxy_ssl_conf_command Groups X25519MLKEM768:X25519;
    proxy_ssl_verify on;
    proxy_ssl_trusted_certificate /etc/ssl/certs/ca.pem;
}

  • Apache httpd: there is no SSLProxy* directive for groups; SSLOpenSSLConfCmd applies to the server side only. The proxy leg takes OpenSSL's default: PQ on the Debian and Alpine images (Tested). On AL2023 it failed with AH02003: SSL Proxy connect failed ... handshake failure until the host policy was set to DEFAULT:PQ (Tested). The alternative is OPENSSL_CONF pointing at a PQ config in the systemd unit (Hosts and OS).

    SSLProxyEngine on
SSLProxyProtocol -all +TLSv1.3
SSLProxyVerify require
SSLProxyCACertificateFile /etc/ssl/certs/ca.pem
ProxyPass /api/ https://backend:8443/

  • HAProxy: curves on each server line, or once in global with ssl-default-server-curves (both accepted by 3.4.7, Tested).

    backend be_api
    server api1 backend:8443 ssl verify required ca-file /etc/ssl/certs/ca.pem sni str(backend) curves X25519MLKEM768:X25519 ssl-min-ver TLSv1.3

  • Envoy: set ecdh_curves in the cluster's UpstreamTlsContext, and set both minimum and maximum version. The upstream maximum defaults to TLS 1.2, so tls_minimum_protocol_version: TLSv1_3 alone fails with NO_SUPPORTED_VERSIONS_ENABLED (Tested). Without ecdh_curves, a PQ-only backend returns 503 (Tested).

    transport_socket:
  name: envoy.transport_sockets.tls
  typed_config:
    "@type": type.googleapis.com/envoy.extensions.transport_sockets.tls.v3.UpstreamTlsContext
    sni: backend
    common_tls_context:
      tls_params:
        tls_minimum_protocol_version: TLSv1_3
        tls_maximum_protocol_version: TLSv1_3
        ecdh_curves: ["X25519MLKEM768", "X25519"]

  • Caddy: tls_curves in the reverse_proxy HTTP transport (Tested; PQ without it too, from Go's default).

    reverse_proxy https://backend:8443 {
    transport http {
        tls_server_name backend
        tls_curves x25519mlkem768 x25519
    }
}

  • Traefik: serversTransport has no curve option (Traefik 3.7 TLS options). The backend leg uses Go's default, which includes X25519MLKEM768 in builds on Go 1.24+ (Tested with 3.7.19).

  • Tomcat as a client (HttpClient, RestTemplate, WebClient inside the webapp) follows the JDK: Java.

Kubernetes ingress and gateways

  • ingress-nginx: ConfigMap ssl-ecdh-curve: "X25519MLKEM768:X25519:prime256v1" and ssl-protocols: "TLSv1.3" (or "TLSv1.2 TLSv1.3"). The v1.14.0 image links OpenSSL 3.5.4, so the upstream leg is PQ by default. The project was retired on 2026-03-24 with no further fixes (Kubernetes blog); plan the move to Gateway API.

  • AWS Load Balancer Controller: the ALB or NLB terminates TLS, so set the PQ security policy with alb.ingress.kubernetes.io/ssl-policy (Ingress) or service.beta.kubernetes.io/aws-load-balancer-ssl-negotiation-policy (Service). Policy names and the target-group leg: Load balancers.

  • Envoy Gateway: ClientTrafficPolicy.spec.tls.ecdhCurves for listeners and EnvoyProxy.spec.backendTLS.ecdhCurves for backends. Both default to X25519 and P-256 (API reference v1.10). Documented; not run here.

  • Istio ingress and egress gateways: meshConfig.tlsDefaults.ecdhCurves or COMPLIANCE_POLICY=pqc (Service mesh).

Verify

  1. Posture. OpenSSL must be 3.5 or later: nginx -V 2>&1 | grep OpenSSL, haproxy -vv | grep 'SSL library', httpd -v plus openssl version. Envoy: envoy --version (BoringSSL; check the config, not the version). Go servers: caddy version, traefik version (Go 1.24+). On AL2023 also update-crypto-policies --show.

  2. Inbound, live. The PQ client must get the hybrid group and the classical client must still connect:

    openssl s_client -connect host:443 -tls1_3 -groups X25519MLKEM768 </dev/null 2>&1 | grep 'Negotiated TLS1.3 group'
# Negotiated TLS1.3 group: X25519MLKEM768
openssl s_client -connect host:443 -tls1_3 -groups X25519 </dev/null 2>&1 | grep 'Peer Temp Key'
# Peer Temp Key: X25519, 253 bits
openssl s_client -connect host:443 -tls1_2 </dev/null   # must fail when the listener is TLS 1.3-only

  3. Upstream, live. Point a test route at a PQ-only backend (openssl s_server -accept 8443 -www -tls1_3 -groups X25519MLKEM768 -cert c.pem -key k.pem) and at a classical-only one (-groups X25519). Both must return HTTP 200 through the proxy.

  4. Logs and metrics. nginx: add $ssl_curve to log_format (Tested: proto=TLSv1.3 cipher=TLS_AES_256_GCM_SHA384 group=X25519MLKEM768). Envoy: admin /stats counters listener.<addr>.ssl.curves.X25519MLKEM768 and cluster.<name>.ssl.curves.X25519MLKEM768 (Tested). Apache httpd and HAProxy log formats have no negotiated-group variable that we found, so use the s_client checks or a packet capture (Network devices and egress).

Pitfalls and rollback

  • Envoy's upstream TLS maximum defaults to 1.2. Setting only the minimum to 1.3 gives NO_SUPPORTED_VERSIONS_ENABLED and 503s. Set both (Tested).

  • Envoy before 1.40 has no ML-KEM by default. Without ecdh_curves, a PQ-only client is refused and a PQ-only backend gives 503 (Tested on 1.36.13). 1.40.0+ includes X25519MLKEM768 by default (Tested on 1.40.2); keep the explicit list so older and pinned builds behave the same.

  • Amazon Linux 2023's crypto policy drops ML-KEM from OpenSSL's defaults, even with OpenSSL 3.5.8. Explicit server directives work; the Apache proxy leg needs the host policy (Tested).

  • Old OpenSSL rejects the name. On OpenSSL 3.0 hosts, a config naming X25519MLKEM768 is expected to fail at load (nginx -t, haproxy -c). Not tested here, so run the config check in CI before rollout.

  • Explicit lists replace the default. Traefik curvePreferences, an nginx ssl_ecdh_curve or a HAProxy curves list without X25519MLKEM768 turns PQ off.

  • PQ-only listeners lock out classical clients. Keep X25519 after the hybrid group on anything internet-facing. One community report describes intermittent failures after forcing PQ-only on nginx (forum thread, Claimed).

  • Larger ClientHello (about 1.2 KB more) can upset old middleboxes on the upstream path: Network devices and egress.

  • ingress-nginx is retired, so fixes have stopped; plan the Gateway API move rather than relying on it long term.

  • Rollback: remove the group directive, or put X25519 first, then reload (nginx -s reload, systemctl reload haproxy, apachectl graceful, Envoy hot restart or xDS push). Clients need no change. On AL2023, update-crypto-policies --set DEFAULT and restart the service.

/etc/nginx/nginx.conf

# /etc/nginx/nginx.conf - PQ hybrid TLS on the listener and on the proxy_pass (upstream) leg
# Needs nginx linked against OpenSSL 3.5+ (nginx:1.29+/stable on Debian 13 or Alpine 3.22+).
worker_processes auto;
events { worker_connections 1024; }

http {
    access_log /dev/stdout;
    error_log  /dev/stderr info;

    # Log the negotiated group per request ($ssl_curve, nginx 1.21.5+).
    log_format tls '$remote_addr "$request" $status proto=$ssl_protocol '
                   'cipher=$ssl_cipher group=$ssl_curve';

    # ---- Server side (inbound) ----
    server {
        listen 8443 ssl;
        server_name srv;
        access_log /dev/stdout tls;

        ssl_certificate     /certs/server.crt;
        ssl_certificate_key /certs/server.key;

        # TLS 1.3 only. Use "TLSv1.2 TLSv1.3" if you still have 1.2-only clients.
        ssl_protocols TLSv1.3;
        # Hybrid first, classical fallback for clients that do not offer ML-KEM.
        ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1;

        location / { return 200 "ok group=$ssl_curve\n"; }
    }

    # ---- Client side (upstream / proxy_pass) ----
    server {
        listen 8080;

        location /pq/ {
            proxy_pass https://be:8443/;          # PQ-only backend
            proxy_ssl_server_name on;
            proxy_ssl_name be;
            proxy_ssl_protocols TLSv1.3;
            # nginx 1.19.4+: pass Groups straight to OpenSSL for the upstream leg.
            proxy_ssl_conf_command Groups X25519MLKEM768:X25519;
            # Production: proxy_ssl_verify on; proxy_ssl_trusted_certificate /etc/ssl/certs/ca.pem;
        }

        location /classic/ {
            proxy_pass https://be:9443/;          # classical-only backend (fallback check)
            proxy_ssl_server_name on;
            proxy_ssl_name be;
            proxy_ssl_protocols TLSv1.3;
            proxy_ssl_conf_command Groups X25519MLKEM768:X25519;
        }
    }
}

# Envoy before 1.40 defaults ecdh_curves to X25519, P-256 (no ML-KEM); 1.40+ adds X25519MLKEM768.
# Set the list on BOTH sides anyway, so every Envoy version in the fleet behaves the same.
admin:
  address: { socket_address: { address: 0.0.0.0, port_value: 9901 } }

static_resources:
  listeners:
  # ---- Server side (downstream TLS) ----
  - name: tls_in
    address: { socket_address: { address: 0.0.0.0, port_value: 8443 } }
    filter_chains:
    - transport_socket:
        name: envoy.transport_sockets.tls
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.transport_sockets.tls.v3.DownstreamTlsContext
          common_tls_context:
            tls_params:
              tls_minimum_protocol_version: TLSv1_3
              tls_maximum_protocol_version: TLSv1_3
              ecdh_curves: ["X25519MLKEM768", "X25519", "P-256"]
            tls_certificates:
            - certificate_chain: { filename: /certs/server.crt }
              private_key: { filename: /certs/server.key }
      filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: tls_in
          access_log:
          - name: envoy.access_loggers.stdout
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.access_loggers.stream.v3.StdoutAccessLog
              log_format:
                text_format_source:
                  inline_string: "%REQ(:PATH)% %RESPONSE_CODE% %DOWNSTREAM_TLS_VERSION% %DOWNSTREAM_TLS_CIPHER%\n"
          route_config:
            virtual_hosts:
            - name: local
              domains: ["*"]
              routes:
              - match: { prefix: "/" }
                direct_response: { status: 200, body: { inline_string: "ok\n" } }
          http_filters:
          - name: envoy.filters.http.router
            typed_config: { "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router }

  # ---- Client side (plain HTTP in, TLS to backends) ----
  - name: http_in
    address: { socket_address: { address: 0.0.0.0, port_value: 8080 } }
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager

            virtual_hosts:
            - name: backends
              domains: ["*"]
              routes:
              - match: { prefix: "/pq/" }
                route: { cluster: be_pq, prefix_rewrite: "/" }
              - match: { prefix: "/classic/" }
                route: { cluster: be_classic, prefix_rewrite: "/" }
          http_filters:
          - name: envoy.filters.http.router
            typed_config: { "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router }

               SSLEnabled="true" maxThreads="50"
               sslImplementationName="org.apache.tomcat.util.net.openssl.OpenSSLImplementation">

        </OpenSSLConf>
        <Certificate certificateFile="/certs/server.crt"

    </Connector>
    <Engine name="Catalina" defaultHost="localhost">

ssm-nginx-pq.tf (Terraform; EC2 on AL2023, run with State Manager or Run Command)

resource "aws_ssm_document" "nginx_pq" {
  name            = "PQ-Nginx-Groups"
  document_type   = "Command"
  document_format = "YAML"
  content         = <<-DOC
    schemaVersion: "2.2"
    description: "Enable X25519MLKEM768 on nginx inbound and proxy_pass legs (AL2023)"
    mainSteps:
      - action: aws:runShellScript
        name: nginxPq
        inputs:
          runCommand:
            - set -euo pipefail
            - nginx -V 2>&1 | grep -q 'OpenSSL 3\.[5-9]' || { echo "nginx OpenSSL < 3.5"; exit 1; }
            - |
              cat > /etc/nginx/conf.d/00-pq-tls.conf <<'EOF'
              # http-level defaults; server blocks inherit unless they override
              ssl_protocols TLSv1.2 TLSv1.3;
              ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1;
              proxy_ssl_protocols TLSv1.2 TLSv1.3;
              proxy_ssl_conf_command Groups X25519MLKEM768:X25519:prime256v1;
              EOF
            - nginx -t
            - systemctl reload nginx
            - echo | openssl s_client -connect 127.0.0.1:443 -tls1_3 -groups X25519MLKEM768 2>&1 | grep 'Negotiated TLS1.3 group'
  DOC
}
