Web application firewalls (WAF)

What decides PQ here

AWS WAF never terminates TLS. The resource it is attached to does: CloudFront, ALB, API Gateway REST, AppSync, Cognito, App Runner, Verified Access, Amplify or Bedrock AgentCore Gateway. So PQ for an AWS WAF-protected app is set on that resource (Load balancers, Edge and API front doors). Shield Advanced and Firewall Manager have no TLS role. Third-party WAFs that run as a reverse proxy (appliance, virtual appliance, SaaS/CDN) terminate TLS themselves, so their own TLS stack and profile decide both the client leg and the origin leg. Software WAF modules (ModSecurity, Coraza) inherit TLS from the host proxy.

Server side: configuration to enable

F5 BIG-IP (17.5.1+; tmsh from F5's PQC chapter; F5's sample output has naming inconsistencies, so check tmsh list after creating):

tmsh create ltm cipher rule PQC_RULE cipher DEFAULT dh-groups X25519MLKEM768:DEFAULT signature-algorithms DEFAULT
tmsh create ltm cipher group PQC_GROUP allow add { PQC_RULE }
tmsh create ltm profile client-ssl clientssl-pq cipher-group PQC_GROUP ciphers none options { dont-insert-empty-fragments }
tmsh create ltm profile server-ssl serverssl-pq cipher-group PQC_GROUP ciphers none

NetScaler ADC (enhanced SSL profile):

bind ssl profile pq_fe_profile -eccCurveName X25519_MLKEM768
# or rebind all curves with the hybrid first
bind ssl profile pq_fe_profile -eccCurveName ALL

FortiWeb 8.0.3+:

config server-policy policy
  edit "app-policy"
    set tls-v13 enable
    set tls-pqc-support enable
    set tls-pqc-groups x25519mlkem768 secp256r1mlkem768 secp384r1mlkem1024
  next
end

Cloudflare: nothing to set for visitors; for origins, keep Automatic key exchange on and make the origin offer X25519MLKEM768. Akamai: enable the PQC behaviors in Property Manager or Delivery Manager; TLS 1.3 must be on. AWS WAF: set the PQ policy on the protected resource.

Verify

AWS WAF logs carry no TLS version, cipher or key-exchange field. Fields include ja3Fingerprint (32 hex) and ja4Fingerprint (36 characters), computed only for CloudFront and ALB (log fields, Documented).

Can fingerprints find non-PQ clients? Not directly:

  • JA4 hashes the sorted extension type codes and signature algorithms. It includes the fact that supported_groups and key_share extensions exist, not their values, so a PQ and a classical build of the same client can share a JA4 (JA4 spec, Documented).

  • JA3's input string does include the supported groups list, but AWS WAF logs only the MD5 hash, so you cannot read the groups back.

  • Use them only as a lookup: find a classical client in the ALB connection log (tls_keyexchange), note its JA4 from the WAF log, then count or label that JA4 in WAF (the label-known-classical-client rule below, Count action). Correlation is by client IP and time, so treat it as a hint.

Use the resource's own logs for the real signal: ALB connection logs and NLB access logs (Load balancers), the CloudFront CloudFront-Viewer-TLS-Details header (Edge and API front doors). F5 has an open community request for logging the negotiated PQ group; no BIG-IP log field was found.

Live test for any WAF that terminates TLS (OpenSSL 3.5 client):

echo | openssl s_client -connect waf.example.com:443 -servername waf.example.com -tls1_3 -groups X25519MLKEM768 2>&1 | grep 'Negotiated TLS1.3 group'
echo | openssl s_client -connect waf.example.com:443 -servername waf.example.com -groups X25519 2>&1 | grep Protocol

Tested here (2026-11-14): ModSecurity CRS nginx image, digest sha256:9a386aa4a9ee...: PQ client negotiated X25519MLKEM768; classical TLS 1.3 and TLS 1.2 clients connected; the WAF proxied to an openssl s_server -groups X25519MLKEM768 -tls1_3 upstream with HTTP 200. 4 of 4 checks passed. Pitfalls, enforcement and rollback

  • An AWS WAF rule cannot require PQ: no request component exposes the key exchange.

  • Firewall Manager can force a web ACL onto every ALB or CloudFront distribution, but not a TLS policy. Use the SCP and Config rules in Load balancers and Enforcement and guardrails.

  • Appliances: PQ needs TLS 1.3 on the profile; older code (BIG-IP before 17.5.1, FortiWeb before 8.0.3) has no ML-KEM, and BIG-IP 17.5.0 only had the draft X25519Kyber768.

  • Passive (out-of-band) WAFs that decrypt from a copied private key cannot read any (EC)DHE session, PQ or not. Move them inline.

  • SaaS WAFs: the client leg can be PQ while the origin leg is not; check both.

  • Rollback: remove the PQ group from the cipher rule or curve binding (appliances), turn off the PQC behavior (Akamai), or revert the resource policy (AWS).

Full configuration files

Terraform and CloudFormation below passed terraform validate (Terraform 1.13.5, aws provider 6.73.0) and cfn-lint 1.60.1. The JA4 value is FoxIO's example string; replace it with one you have tied to a classical client.

iac/waf/main.tf

terraform {
  required_version = ">= 1.6"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

provider "aws" {
  region = "us-east-1"
}

variable "alb_arn" { type = string }

resource "aws_wafv2_web_acl" "app" {
  name  = "app-regional"
  scope = "REGIONAL"

  default_action {
    allow {}
  }

  rule {
    name     = "aws-common"
    priority = 10
    override_action {
      none {}
    }
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesCommonRuleSet"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "aws-common"
      sampled_requests_enabled   = true
    }
  }

  # Count (never block) a client fingerprint you have confirmed is classical.
  rule {
    name     = "label-known-classical-client"
    priority = 20
    action {
      count {}
    }
    statement {
      byte_match_statement {
        search_string         = "t13d1516h2_8daaf6152771_02713d6af862"
        positional_constraint = "EXACTLY"
        field_to_match {
          ja4_fingerprint {
            fallback_behavior = "NO_MATCH"
          }
        }
        text_transformation {
          priority = 0
          type     = "NONE"
        }
      }
    }
    rule_label {
      name = "pq:classical-client"
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "classical-client"
      sampled_requests_enabled   = true
    }
  }

  visibility_config {
    cloudwatch_metrics_enabled = true
    metric_name                = "app-regional"
    sampled_requests_enabled   = true
  }
}

resource "aws_wafv2_web_acl_association" "alb" {
  resource_arn = var.alb_arn
  web_acl_arn  = aws_wafv2_web_acl.app.arn
}

resource "aws_cloudwatch_log_group" "waf" {
  name              = "aws-waf-logs-app-regional" # must start with aws-waf-logs-
  retention_in_days = 90
}

resource "aws_wafv2_web_acl_logging_configuration" "app" {
  resource_arn            = aws_wafv2_web_acl.app.arn
  log_destination_configs = [aws_cloudwatch_log_group.waf.arn]
}

# Firewall Manager: a WAF web ACL on every ALB in the organisation (no TLS policy type exists).
resource "aws_fms_policy" "waf_on_albs" {
  name                  = "waf-on-all-albs"
  exclude_resource_tags = false
  remediation_enabled   = true
  resource_type         = "AWS::ElasticLoadBalancingV2::LoadBalancer"

  security_service_policy_data {
    type = "WAFV2"
    managed_service_data = jsonencode({
      type = "WAFV2"
      preProcessRuleGroups = [{
        ruleGroupArn   = null
        overrideAction = { type = "NONE" }
        managedRuleGroupIdentifier = {
          vendorName           = "AWS"
          managedRuleGroupName = "AWSManagedRulesCommonRuleSet"
        }
        ruleGroupType = "ManagedRuleGroup"

      }]

      defaultAction                     = { type = "ALLOW" }

    })
  }
}

tests/run-modsec-pq.sh (the software-WAF test; needs Docker)

#!/bin/bash
set -u
L="--label run=pqc-deep-edge"; NET=pqc-deep-edge-net
DEB=$(docker image inspect --format '{{index .RepoDigests 0}}' debian:trixie-slim)
WAF=$(docker image inspect --format '{{index .RepoDigests 0}}' owasp/modsecurity-crs:nginx)
docker network create $L $NET >/dev/null
# PQ-only upstream
docker run -d $L --network $NET --name edge-pqonly $DEB bash -c '
apt-get -qq update >/dev/null 2>&1; apt-get -qq install -y openssl >/dev/null 2>&1
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes -keyout /k.pem -out /c.pem -subj /CN=pqonly -days 2 2>/dev/null
exec openssl s_server -accept 4433 -cert /c.pem -key /k.pem -tls1_3 -groups X25519MLKEM768 -www' >/dev/null
for i in $(seq 1 60); do docker logs edge-pqonly 2>&1 | grep -q ACCEPT && break; sleep 2; done
# ModSecurity CRS nginx in front of it
docker run -d $L --network $NET --name edge-modsec -e BACKEND=https://edge-pqonly:4433 -e PROXY_SSL_VERIFY=off $WAF >/dev/null
sleep 8
# client leg: PQ-only, classical, TLS 1.2
docker run --rm $L --network $NET $DEB bash -c '
apt-get -qq update >/dev/null 2>&1; apt-get -qq install -y openssl >/dev/null 2>&1
echo | openssl s_client -connect edge-modsec:8443 -groups X25519MLKEM768 -tls1_3 2>&1 | grep "Negotiated TLS1.3 group"
echo | openssl s_client -connect edge-modsec:8443 -groups X25519 2>&1 | grep "^Protocol"
echo | openssl s_client -connect edge-modsec:8443 -tls1_2 2>&1 | grep "^Protocol"'
# origin leg: through the WAF to the PQ-only upstream
docker run --rm $L --network $NET $DEB bash -c 'apt-get -qq update >/dev/null 2>&1; apt-get -qq install -y curl >/dev/null 2>&1; curl -sk -o /dev/null -w "HTTP %{http_code}\n" https://edge-modsec:8443/'
docker rm -f edge-pqonly edge-modsec >/dev/null; docker network rm $NET >/dev/null
